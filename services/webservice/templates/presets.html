{#- The Presets page — the MizEdit preset files this installation names, one TILE per preset. The page is a READ. A preset is one top-level key of one discovered preset file; its tile is the console's OWN tile component (``_tiles.html``, the same macro the settings landing and the node page draw), carrying the preset's name, its kind badge and the top-level keys it writes — the schema's own key names, printed as data and never translated. A preset has no on/off state, so the tile's switch is not drawn (``sw=none``): the foot is the trash and the cog. Every tile also carries the YAML DOOR — an optional link the shared tile component draws only when a URL is passed (``card.yaml_url``, empty for a caller without ``presets.view``). It opens the preset's own one-block editor, which is how a preset created by the wizard becomes an expert-DSL preset. The cog opens the wizard at the URL the page module declares; a preset the wizard does not open (the ``modify`` expert DSL) states its own note in the tile's body and carries the YAML door as its only editor — no cog is drawn beside it. The trash is a LINK to this page's own confirm surface (``?remove=``), which shows the preset's document and EVERY reference to it and posts to the ONE write route. A preset that is still referenced carries no trash: the confirm page could only refuse it, so the tile states the refusal itself — the SAME sentence and the SAME reference labels the confirm page prints, in the tile's own ``st-note`` (the shape the ``modify`` preset's note already uses). A removable preset carries the trash and no such note. The toolbar is a real GET with no JavaScript: the tab strip carries ``?file=``, the kind chips carry ``?kind=``, the search box carries ``?q=``, and each keeps the other two. The strip is drawn only when the installation carries more than one preset file.
