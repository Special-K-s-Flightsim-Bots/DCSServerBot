{#- THE ONE-SHOT NOTICE of a write — the outcome of the action that just ran, shown ONCE. Why it is not the attention banner (`_banner.html`): that banner is DERIVED FROM LIVE STATE on every render and is part of the dashboard's state panel, which a live refresh swaps. This is a fact about what JUST HAPPENED. The page's context POPS it out of the session (`pages/actions. pop_notice`), so a reload — or the next live refresh — does not repeat it. It re-derives nothing: `notice.message` is the action's own message and `notice.ok` its own `success`, read off the typed result. `notice.audit_warning` is rendered rather than swallowed: when the audit trail could not be written the action still reports its real outcome, and the page says so IN WORDS — a green banner over a lost audit entry is the one combination that must never be silent. `notice.apply` IS THE "APPLY NOW" CONTROL, and it is DATA rather than a second write path: a save fills it with the file's identity, the session's CSRF token and the one-shot token its confirmation needs (`config_apply.offer`). A notice without it — a refused save, a save that changed nothing, a file read at the next launch — renders no control at all. It is a plain POST form, so it works with JavaScript off, and it opens the CONFIRMATION instead of applying anything. `notice.pending` marks the notice a STARTED apply leaves: the page then reloads itself once (`base.html`'s head reads the same flag) and this block offers the same thing as a link, so an operator whose browser dropped the reload still has a way to ask again. Absent when there is nothing to say: `notice` is undefined on a page that has no write, and `None` when nothing just happened. No empty box, no placeholder — a console that reports nothing is the healthy state. -#} {% if notice is defined and notice %} {% set apply = notice.get('apply') %}
