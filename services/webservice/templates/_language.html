{#- THE LANGUAGE CONTROL — one partial, rendered by the shell (base.html) and by the login page (login.html), which does not extend the shell and so cannot inherit it. IT IS A PILL PLUS A MENU. The pill draws the language IN FORCE (its flag and its own endonym) and is the menu's trigger; the menu lists every language that has a `webui` catalog, one row each, the current row ticked. A flat row of all flags stops fitting as languages are added, and a flag alone never says which language it is — inside a menu there is room for both the flag and the name. It is PLAIN LINKS, never a form and never a script: each row is a GET to the shell's own /language route, which stores the choice in its own cookie and sends the visitor back to `next`. That is deliberately session-free, so a visitor can pick a language on the login page BEFORE signing in — and the page stays fully usable with JavaScript off. The menu is a native `popover` opened by its button (`popovertarget`), which the browser also closes on Escape or a click outside; no script is involved, and the top layer keeps it from being clipped by the bar. Each flag is a real static SVG, never an emoji — Windows renders flag emoji as the two regional-indicator letters, which would look broken on the maintainer's own machine. The language's OWN endonym is the row's text, so the name is drawn from the language itself rather than translated. `language` is built by services.webservice.i18n.language_control and passed by every page that renders the shell; the `is defined` guard keeps the standalone renders a test makes (which pass no request) free of a control that would have nowhere to point. The options are exactly the languages that have a `webui` catalog, so no option can render an untranslated page. -#} {% if language is defined and language %}
