{#- THE GLYPH SET — one inline SVG per control, on the standard 24px grid (`stroke 2`, `currentColor`), drawn at 16px inside a 28px button. No icon font, no CDN, no sprite, no emoji (emoji render differently per platform and would break the console's one-colour glyph language). ONE PLACE, TWO READERS: the row strip (`_strip.html`, a server row today) and the confirm dialog (`confirm.html`, its warning mark). A glyph pasted into a template instead of asked for here is the second copy that drifts the first time a shape is fixed. ONE DRAWING PER OPERATION — the decision of 2026-09-29 evening, which CORRECTS the same day's rule ("one glyph per meaning", startup = start = unpause). That rule collapsed three controls onto one triangle; the corrected rule is that the triangle means "bring a DOWN server up", and PAUSED is not down — it is a frozen RUNNING server — so Unpause is a different operation from Startup and Start, and keeps the mockup's own bar+triangle drawing that rule replaced: | control | state it appears in | drawing | |------------|---------------------|-----------------------------| | `startup` | SHUTDOWN | the bare play triangle | | `start` | STOPPED | the bare play triangle | | `unpause` | PAUSED | bar + triangle | | `pause` | RUNNING | two bars | | `shutdown` | RUNNING, PAUSED | the single power arc | | `restart` | RUNNING, PAUSED | the circular arrow | | `dcs_update` | node declares DCS | two opposed vertical arrows | | `stop` | RUNNING, PAUSED | the filled square (row menu)| `startup` and `start` share the triangle safely because their states are DISJOINT: no row is ever in both SHUTDOWN and STOPPED, so one strip never shows that drawing twice. **THE INVARIANT every future change must keep: no single state offers two controls wearing the same drawing.** A PAUSED row shows bar+triangle, the power arc and the circular arrow — no plain triangle. The old Startup glyph (a CLOSED ring with a short bold stem) is DELETED: **the power arc is "shut it down"**, worn by `shutdown` (RUNNING, PAUSED) and shared with the node row's `shutdown`, and it is now the ONLY power drawing in the set — which also removes the two-power-glyphs-one-row ambiguity reported ("shows the 'power' button, the same as when it is started up and to shut it down"). WHY NOT `⏫` FOR STARTUP (the maintainer's other suggestion of 2026-09-29 — recorded so it is NOT re-proposed): an up arrow already means two other things in this same glyph set and on the same screen — `online` (a box with an arrow rising) and `upgrade` (an arrow rising out of a tray). A third rising arrow would carry the NODE rows' meaning into the server row's first control. The triangle has no such twin: `pause` is the two bars, `restart` the circular arrow, `stop` the filled square. The 2026-09-28 mockup (`mockups/dcssb-admin-ui/dashboard-actions`, whose `_build.py` holds the set) is the design source of record. The strip now follows the maintainer's 2026-09-29 decision (): the mockup is AUTHORITATIVE for the bar+triangle Unpause drawing — it drew it and the corrected rule replaced it — and is NOT edited. Still standing from the 2026-09-28 set (unchanged): * **Popup is the bubble FILLED** (a knocked-out dot, so the fill reads at 16px where the mockup's bold "!") while **Chat keeps the outlined bubble** with its text lines; * **Kick is simplified** to an arrow leaving a barrier — see the note on the glyph itself; * the node row shares `restart` and `shutdown` with the server row — the same two operations one level up — and owns `upgrade` (an arrow rising out of a tray: update and restart); * the node row's MAINTENANCE PAIR is the mockup's own `online`/`offline` artwork: the same box twice, with the arrow above it pointing up (bring the servers online) and the arrow below it pointing down (take them offline). One box, one mirrored arrow — a coherent pair, and the mockup drew it for exactly these two words (`dashboard-actions/_build.py`, its glyph legend). It was left out of the first pass because that pass's three controls were NOT these words; reusing the reviewed pair beats inventing a second drawing. THE MAINTENANCE FLAG PAIR is on the SERVER row and draws TWO NEW shapes, and they must be new: the flag controls apply in EVERY server state (a flag is not a power state), so they are drawn beside every other glyph on some row — `startup`/`start` (triangle), `unpause` (bar+triangle), `pause` (two bars), `shutdown` (the power arc), `restart` (circular arrow) and `stop` (filled square) are all taken, and the invariant above forbids a second copy of any of them. * `maintenance` — a CONE, the one drawing everybody reads as "this is out of service": a trapezoid with a stripe. Deliberately NOT the `warn` triangle (that mark belongs to the dialog's warning) and not a flag/pennant, which at 16px is a sliver; * `end_maintenance` — the same idea RELEASED: a check inside a circle ("all clear"), which also reads as the opposite of `ban` (a circle with a diagonal). THE TRANSPORT GLYPHS are `play`, `stop`, `skip`, `repeat` and `shuffle`, drawn for the music player (`_music_player.html`). `play` wears the SAME bare triangle as `startup`/`start` — the drawing means "start it", and a transport strip is never drawn on a row that also offers Startup or Start, so the invariant above holds for the three names together. `stop` is the row menu's own filled square, and there is NO PAUSE DRAWING in the strip: the radio transport is play / stop / skip / mode, where Stop IS the pause, so `pause` (the two bars) belongs to the server row alone. The mode button draws the mode IN FORCE — `repeat` or `shuffle` — and posts the other one. `title` and `aria-label` are NOT drawn here: they belong to the CONTROL (one per button, naming its target), never to a bare glyph. THE SECRET-REVEAL PAIR is the two glyphs the Configuration tab's password row needs: `reveal` is the open eye, `conceal` the same eye struck through. One button wears both and swaps between them (`aria-pressed`; see `.cfg-reveal` in shell.css), so the shape states the state as plainly as the colour does. THE `trash` GLYPH IS DELETED. It had exactly ONE reader — the Missions tab's per-row Remove — and that control was removed (a mission is removed by ticking its row and pressing the card's one action). A drawing is kept by having a CONTROL, never by being available: with no reader left it is gone, exactly as the old Startup ring was DELETED when its own control changed. `ban` is untouched (it belongs to the player row), and the set now carries no delete glyph because no surface deletes. `pencil` is the Bans row's EDIT: a shaft with a squared-off point drawn on the diagonal, the universal "rewrite this row" mark. A ban entry is edited, never configured, so it takes no cog: the row's own door into its page is its NAME. THERE IS NO COG IN THIS SET, AND NO ROW DRAWS ONE. A row's NAME is the door into that entity's page, so a second glyph pointing at the same page is a navigation duplicate sitting beside a strip of ACTIONS. The one cog the console draws is the settings TILE's — the door into that item's own editor — and it is drawn by `_tiles.html`'s `cog()` macro (`st-cog`, beside the label it carries), never asked for here. `unban` is the Bans row's LIFT: an OPEN padlock (the shackle lifted clear of the body), the one drawing that reads as "this restriction is released". It is deliberately NOT `unmute` (the MUTE pair's loudspeaker on a player row, which says nothing about a ban), NOT `ban` (the ban itself) and NOT `end_maintenance`'s check-in-circle. `mods` is the Nodes row's door into that node's ROOT-MODS page: a BOX with an arrow entering it — packages going into an installation. It is deliberately NOT `download` (an arrow sinking into a tray: handing a FILE over) and NOT `online`/`offline` (a box with a mirrored arrow, which is the node's power): the box here is closed on every side and the arrow comes in from OUTSIDE it. `dcs_update` is the NODE row's DCS installation: two vertical arrows side by side, pointing OPPOSITE ways (a swap). One control covers update, rollback and branch switch — the engine call takes a branch and a version — so the drawing states the OPERATION (this build is replaced by another one) and never a direction: an up arrow alone would claim "newer only" and a down arrow alone "older only". It cannot be confused with its three neighbours on the same row: `upgrade` is an arrow rising out of a tray (a CONTAINER plus one arrow), `download` an arrow sinking into one (the same container, the other direction), and `restart` is the circular arrow — a ring, not a pair of shafts. No container, no ring and no single full-height arrow is used here, which is what keeps it tellable apart at 16px.
